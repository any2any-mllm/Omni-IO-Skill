# Asset Registry

The registry persists as a JSON file at `$OMNI_OUTPUT_DIR/registry.json`.
**All reads and writes go through MCP tools; Claude never reads or writes the JSON file directly.**
Writes are atomic, using a temporary file followed by rename. On macOS and Linux, a file lock also serializes writes so concurrent registration from multiple MCP server processes, such as several open sessions, cannot overwrite one another. Windows has no `fcntl`, so it skips the lock but retains atomic writes.

---

## 1. Purpose

The **asset registry** records every asset successfully generated in the workspace and enables reuse across turns:

1. **Cross-turn references:** When the user says, "Turn the last image into a 3D model," Claude finds the local asset path in the registry.
2. **Avoid duplicate generation:** Claude checks the registry first and reuses an existing compatible asset when possible.
3. **Context compression:** Historical assets enter planning as `asset_id` references rather than consuming substantial context.

---

## 2. Registry Structure

The MCP server automatically writes each record when generation completes; Claude does not construct the record manually:

```json
{
  "img_a3f2c1": {
    "asset_id": "img_a3f2c1",
    "type": "image",
    "url": "/Users/alice/Documents/OmniIO/img_a3f2c1.png",
    "description": "A generated forest-mist wallpaper in warm tones and a 16:9 landscape layout, with no people and a quiet, restorative atmosphere.",
    "params_used": { "aspect_ratio": "16:9" },
    "turn_id": "turn_20250617_1437",
    "completed_at": 1749520015
  },
  "mus_b4e8d2": {
    "asset_id": "mus_b4e8d2",
    "type": "audio",
    "subtype": "music",
    "url": "/Users/alice/Documents/OmniIO/mus_b4e8d2.mp3",
    "description": "Thirty seconds of generated New Age ambient meditation music, with a piano melody, approximately 72 BPM, and no vocals.",
    "params_used": { "duration_seconds": 30, "instrumental": true },
    "turn_id": "turn_20250617_1437",
    "completed_at": 1749520025
  }
}
```

| Field | Description |
|-------|-------------|
| `asset_id` | Unique identifier in `{prefix}_{6-digit hex}` format, generated by the MCP server |
| `type` | `image` / `video` / `audio` / `3d` / `document` / `code` |
| `subtype` | Audio: `music` / `sfx` / `speech`; document: `ppt` / `word` / `pdf` / `excel` / `markdown`; code: e.g. `webpage`; image/video: Expert-assembled final output such as `poster` with `asset_type="image"` or `produced_video` with `asset_type="video"` |
| `url` | Absolute local file path under `OMNI_OUTPUT_DIR` |
| `description` | Natural-language description written automatically during generation |
| `turn_id` | Turn identifier set by Claude at the start of the current turn, used to distinguish outputs from different conversation turns |

## 3. Claude's Workflow

### 3.1 Start of Each Turn: Set `turn_id`

**Whenever a user message includes a generation task**, call the following before any generation tool:

```
set_turn("turn_YYYYMMDD_HHmm")
```

Use the current time to the minute, for example `turn_20250617_1437`.

This tags all assets generated in the turn consistently so a later reference such as "the last image" can be resolved precisely.

### 3.2 Generation Tasks: Automatic Registration

After each generation tool, such as `generate_image` or `generate_video`, finishes, the MCP server automatically writes the asset to the registry and returns the complete asset record:

```json
{
  "asset_id": "img_a3f2c1",
  "type": "image",
  "url": "/Users/alice/Documents/OmniIO/img_a3f2c1.png",
  "description": "...",
  "turn_id": "turn_20250617_1437"
}
```

**Claude does not need to write any file.**

### 3.3 Exception: Register `code` and `markdown` Manually

`code` and `markdown` tasks do not pass through a `generate_*` tool. Claude writes their files natively with Write/Edit, so they **are not registered automatically**. After writing the file, call:

```
register_asset(asset_type="code", subtype="webpage", url="<file path>", description="...", params_used={...})
register_asset(asset_type="document", subtype="markdown", url="<file path>", description="...", params_used={...})
```

If this step is skipped, the file remains an orphan with no `asset_id`; later turns cannot find it or reference it with `asset_ref`. See `skills/generate/code.md` and `skills/generate/markdown.md`.

Expert-assembled final outputs such as posters and complete videos are also produced internally through `code` tasks and therefore require manual `register_asset()` calls. Register them with the output's actual modality, `image` or `video`, rather than `"code"`, because the registry describes what the file is, not how it was created. See the corresponding Expert document.

### 3.4 Find Historical Assets with `list_assets()`

When a user references historical content such as "the last image" or "the music from before," call:

```
list_assets()
```

It returns all registered assets in reverse completion-time order. Use `turn_id`, `type`, and semantic matching on `description` to locate the target.

If the exact `asset_id` is known, call:

```
get_asset("img_a3f2c1")
```

---

## 4. Referencing a Historical Asset in `declare`

To reuse a historical asset directly without regenerating it, declare `asset_ref`:

```json
{
  "id": "img1",
  "type": "image",
  "asset_ref": "img_a3f2c1"
}
```

Claude treats an `asset_ref` node as complete and supplies its `url` directly to downstream tasks without making an API call.

---

## 5. Lifecycle Summary

| Event | Claude's Action |
|-------|-----------------|
| A user message includes a generation task | Call `set_turn("turn_YYYYMMDD_HHmm")` |
| A generation tool finishes | None; the MCP server registers the result automatically |
| A `code` or `markdown` task writes a file natively | Call `register_asset()` manually or the file will not be registered |
| The user references a historical asset | Call `list_assets()` and locate the asset semantically |
| A downstream task needs an upstream asset path | Extract the `url` from the upstream tool result and inject it directly |
| Reusing a historical asset across turns | Use `asset_ref` in the `declare` block |

# Skill: 3D-Model Generation

## Trigger

The `declare` block contains a task with `type: "3d"`.

---

## Tool

**Default: Tripo3D v2** (free credits upon registration)  
**Alternative: Meshy v2** (free tier available)

- Configuration: `config.yaml → generate.3d`
- Required API key: `TRIPO_API_KEY` by default, or `MESHY_API_KEY` after switching
- Note: Meshy image-to-3D also requires Cloudinary credentials (`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET`) to turn a local image into a public URL.
- Call: MCP tool `generate_3d(prompt, reference_image_url?)`
- Output is always **GLB**, the most broadly compatible format for mainstream 3D software. Conversion to OBJ, FBX, or other formats is not currently supported.

---

## Inputs

| Field | Source | Description |
|-------|--------|-------------|
| `prompt` | `declare` block | 3D-model description, including appearance, style, and pose |
| `reference_image_url` | Injected from upstream when depending on an image | Automatically injected from the completed upstream image as a visual reference |

---

## Procedure

1. **Resolve parameters:** Read the prompt and check for an upstream reference image.
2. **Choose the tool:** Use the provider configured in `config.yaml`, Tripo by default.
3. **Handle the reference:** If `reference_image_url` is present, use image-to-3D with the image as the visual reference; otherwise use text-to-3D.
4. **Call the API:** Send the 3D-generation request.
5. **Poll:** 3D generation is a long asynchronous task, usually 30–120 seconds. Poll until completion.
6. **Process the result:** Obtain the local path of the GLB file.
7. **Return status:** Return the result as an `output_format` asset object.

---

## Output Format

```json
{
  "task_id": "3d1",
  "type": "3d",
  "asset_id": "3d_{6-digit-hex}",
  "status": "completed",
  "url": "/path/to/workspace/3d_{hex}.glb",
  "description": "A generated 3D model of {description} in {style}, in GLB format for direct import into mainstream 3D software.",
  "params_used": { "provider": "tripo" },
  "depends_on": "img1",
  "completed_at": 1749520090
}
```

---

## Generation Modes

| Mode | Trigger | Quality |
|------|---------|---------|
| Image-to-3D | `depends_on` an upstream image task | Higher, with a visual reference |
| Text-to-3D | No upstream image dependency | Standard |

Recommendation: When a character or object's appearance has specific requirements, generate a reference image first and then use it for 3D generation. This produces more consistent output.

---

## Integration with Other Skills

- **Upstream image, recommended:** A visual reference substantially improves 3D accuracy and detail.

---

## Error Handling

| Error | Handling |
|-------|----------|
| API key not configured | Ask the user to set `TRIPO_API_KEY`, or switch to Meshy and set `MESHY_API_KEY` |
| Meshy image-to-3D lacks Cloudinary configuration | Ask for the three Cloudinary environment variables or switch back to Tripo |
| Generation exceeds `max_wait_seconds` | Mark `failed` and ask the user to retry |
| Unsupported reference-image format | Omit the reference, fall back to text-to-3D, and notify the user |

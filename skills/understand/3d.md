# Skill: 3D-Content Understanding

## Trigger

The user uploads a 3D file and asks to:

- Describe the model: "What is this?"
- Analyze its geometry or components
- Use its shape as a reference for later generation
- Evaluate whether it is suitable for rendering

---

## Inputs

| Format | Description |
|--------|-------------|
| `.ply` / `.xyz` | Point cloud with spatial coordinates and optional color/normals |
| `.glb` / `.gltf` | Standard 3D mesh with materials and textures |
| `.obj` + `.mtl` | Traditional mesh with companion material file |
| `.fbx` | Rigged/animated model with skeletal information |

---

## Analysis Dimensions

**Shape and structure**

- Overall form: organic, mechanical, architectural, terrain, etc.
- Main components and spatial relationships
- Symmetry and repeated structures

**Dimensions and proportions**

- Estimated bounding box: length × width × height
- Relative proportions of components
- Inferred units, when possible

**Surface and materials**, when present in GLB/OBJ

- Main materials: metal, fabric, skin, wood, etc.
- Color distribution
- Estimated texture count and resolution

**Model quality**

- Polygon scale: low, medium, or high poly
- Holes or non-manifold edges affecting printing/rendering
- UV unwrap state, when observable
- Rigging or animation data

**Semantic understanding**

- Object category: character, vehicle, building, prop, etc.
- Likely use: game asset, industrial model, 3D print, etc.
- Style: realistic, low-poly, cartoon, etc.

---

## Tool

**One call: `understand_3d(file_url)`**. It collects trimesh metadata and automatically renders through Blender or the trimesh fallback. Claude does not write a script.

No API key is required. The tool detects Blender at `/Applications/Blender.app` or on `PATH`:

- **With Blender:** Runs headless Blender using Cycles, 64 samples, three-point lighting, and an 800×800 output. It selects the importer by format: GLB/GLTF → `import_scene.gltf`; OBJ → `wm.obj_import`; FBX → `import_scene.fbx`. It produces one textured and lit isometric render. After a 120-second timeout or render failure, it falls back automatically.
- **Without Blender, or after failure/timeout:** Uses matplotlib's Agg backend to create solid-color front, side, and isometric views. These show geometry only and cannot represent materials or textures.

The returned `render_method` is `"blender"` or `"trimesh_fallback"`. Check it before describing the result. For `trimesh_fallback`, tell the user honestly that the renders do not represent materials or true appearance and are suitable only for evaluating geometry.

---

## Procedure

1. **Call `understand_3d(file_url)`:** In one call, obtain geometry metadata—vertices, faces, dimensions, and watertightness—plus `render_paths` and `render_method`.
2. **Read the renders:** Use vision to analyze shape, style, structure, and likely purpose. When `render_method` is `trimesh_fallback`, state that the render has no materials and shows geometry only.
3. **Format for the goal:**
   - Content description: Combine metadata and vision into shape, style, and semantic category.
   - Quality assessment: Focus on polygon scale, `is_watertight`, and dimensional proportions.
   - Generation reference: Extract shape features into a prompt for `generate/image` or `generate/3d`.

---

## Output Formats

**Content description:**

```
Category: mechanical prop
Overall shape: cylindrical body with a hexagonal knob on top and a triangular support below
Symmetry: axial symmetry around Y
Material: dark gray metal with wear around the knob
Style: realistic industrial
```

**Quality assessment:**

```
Faces: approximately 12,000 (medium poly)
Topology: no obvious holes
UVs: unwrapped with no obvious stretching
Materials: two 2K PBR texture sets
Recommendation: suitable for real-time rendering; inspect the interior before printing
```

**Generation reference:**

```
Shape description: cylindrical mechanical component, hexagonal knob, triangular base, industrial dark-gray metal
Suitable as the base prompt for generate/image or generate/3d
```

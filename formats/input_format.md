# Input Format Specification

This file defines the structured input format Claude uses to process user requests.

A user's original input may contain multiple modalities, such as text instructions, images, audio, video, and documents. The appropriate understanding tool first converts each modality into a dense caption. The captions are then assembled into one JSON object according to this specification for Claude to use when planning the execution graph.

---

## Overall Structure

```json
{
  "instruction": "{the user's original text input}",
  "assets": [
    { ... },   // One object per input asset, in the order supplied by the user
    { ... }
  ],
  "history_assets": [  // Optional: relevant assets from previous turns
    { ... }
  ]
}
```

---

## Asset Object Fields

Each asset object contains the following fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | `"image"` / `"video"` / `"audio"` / `"document"` / `"3d"` |
| `asset_id` | string | Yes | Unique identifier within the session, formatted as `{type_abbreviation}_{sequence}`, such as `img_001` |
| `source` | string | Yes | `"user upload"` / `"generated in previous turn"` |
| `description` | string | Yes | Complete natural-language description of the asset, written in sentences rather than as a keyword list |
| `subtype` | string | No | Audio only: `"speech"` / `"music"` / `"sfx"` |
| `transcript` | string | No | Speech only: timestamped transcript |
| `timeline` | array | No | Video only: segmented timeline description |
| `content` | string | No | Document only: extracted body text in Markdown |
| `mesh_info` | object | No | 3D only: metadata such as vertex, face, and material counts |

## Examples by Modality

### Image

Claude's native vision generates `description` as a complete natural-language paragraph:

```json
{
  "type": "image",
  "asset_id": "img_001",
  "source": "user upload",
  "description": "A nighttime city photograph. Colored neon light reflects from rain-wet pavement on an empty street. The image uses a low-angle perspective, cool blue tones, and shallow depth of field, with buildings and signs as its main subjects. The overall mood is a lonely, oppressive cyberpunk atmosphere."
}
```

### Video

Generated by the Gemini 2.5 Flash API. `description` covers the overall content, while `timeline` provides temporal details:

```json
{
  "type": "video",
  "asset_id": "vid_001",
  "source": "user upload",
  "description": "An approximately 45-second empty establishing shot of a city street at night. No people appear. The camera advances slowly in one long take, with a gentle editing rhythm and no obvious cuts. The color palette is cool, with rain and low-frequency electronic ambience in the background.",
  "timeline": [
    { "time": "00:00–00:15", "description": "High-angle wide shot of the illuminated city." },
    { "time": "00:15–00:35", "description": "Eye-level tracking shot down the street, with neon close-ups and clear pavement reflections." },
    { "time": "00:35–00:45", "description": "Close-up of raindrops striking the pavement, followed by a slow fade-out." }
  ]
}
```

### Audio (Speech)

The Gemini API transcribes speech when `GEMINI_API_KEY` is configured; otherwise the workflow falls back to OpenAI Whisper. `description` covers the speaker and tone, while `transcript` contains the transcription:

```json
{
  "type": "audio",
  "asset_id": "aud_001",
  "source": "user upload",
  "subtype": "speech",
  "description": "A recording of one person speaking in a formal, steady tone and introducing the project's background.",
  "transcript": "[00:00:02] Hello everyone. Today we'll introduce the background of this project.\n[00:00:08] The core problem we hope to solve is..."
}
```

### Audio (Music / Environmental Sound)

The Gemini API analyzes the audio when `GEMINI_API_KEY` is configured; otherwise the workflow falls back to Qwen2-Audio. `description` is written in complete sentences:

```json
{
  "type": "audio",
  "asset_id": "aud_002",
  "source": "user upload",
  "subtype": "music",
  "description": "An ambient electronic track with a melancholy, contemplative mood at approximately 85 BPM. The main instruments are synth pads, a low-frequency drum machine, and tremolo guitar, with no vocals. Its lonely atmosphere suits a nighttime urban scene."
}
```

```json
{
  "type": "audio",
  "asset_id": "aud_003",
  "source": "user upload",
  "subtype": "sfx",
  "description": "An outdoor environmental recording dominated by moderately heavy to heavy rain, with rich background layers of occasional thunder, distant traffic, and dripping water. It has a broad sense of space and an oppressive, gloomy rainy-night atmosphere."
}
```

### Document

Extracted by the Mistral OCR 3 API. `description` is a summary sentence and `content` contains the body:

```json
{
  "type": "document",
  "asset_id": "doc_001",
  "source": "user upload",
  "description": "A 12-page Q1 2026 market analysis report. It states that the market grew 15% year over year this quarter, concentration among leading brands continued to increase, and smaller brands face substantial pressure.",
  "content": "# Q1 2026 Market Analysis Report\n## 1. Market Overview\nThe market reached US$XXX billion this quarter, up 15% year over year...\n## 2. Competitive Landscape\n| Brand | Market Share | YoY Change |\n|-------|--------------|------------|\n| A | 32% | +3% |\n..."
}
```

### 3D

trimesh extracts the geometry metadata. If Blender is installed locally, Blender runs headlessly to render a textured isometric view; otherwise the workflow falls back to multi-angle matplotlib renders. Claude's native vision interprets the render and generates `description`:

```json
{
  "type": "3d",
  "asset_id": "3d_001",
  "source": "user upload",
  "description": "A 3D model of a short-haired female humanoid wearing science-fiction light armor. She holds a long, slender weapon in her left hand and has a mechanical prosthetic right arm. The medium-detail model has a stylized-realistic science-fiction look, with dark gray metallic surfaces, blue highlights, PBR skin materials, and an approximate bounding box of 1.2 m × 0.8 m × 1.6 m.",
  "mesh_info": {
    "vertices": 8420,
    "faces": 12300,
    "materials": 2,
    "file_format": ".glb"
  }
}
```

## Complete Assembly Example

The user uploads an image and a music track, then requests a wallpaper, background music, and a short video:

```json
{
  "instruction": "Use the atmosphere of this image and the style of this music to create a high-resolution wallpaper, 30 seconds of meditation music, and a 15-second video that begins with this image.",
  "assets": [
    {
      "type": "image",
      "asset_id": "img_001",
      "source": "user upload",
      "description": "A nature photograph of a forest at dawn. Mist drifts among tall trees as warm, diffused yellow light shines diagonally through gaps in the canopy and illuminates moss on the ground. No people are present. The warm, high-contrast image has a quiet, ethereal, restorative atmosphere."
    },
    {
      "type": "audio",
      "asset_id": "aud_001",
      "source": "user upload",
      "subtype": "music",
      "description": "A New Age ambient instrumental with a piano melody, string pads, and natural birdsong. The tempo is relaxed at about 72 BPM, with no vocals. The mood is calm and meditative with a slight melancholy."
    }
  ]
}
```

---

## Length Limits

Keep `description` fields reasonably short so they do not dilute Claude's attention while planning:

| Modality | Maximum `description` Length | Maximum `content` / `transcript` Length |
|----------|------------------------------|-----------------------------------------|
| Image | 150 characters | — |
| Video | 200 characters including `timeline` | — |
| Audio (speech) | 80 characters | 1,000-character transcript |
| Audio (music/environmental sound) | 120 characters | — |
| Document | 100 characters | 2,000-character body |
| 3D | 150 characters | — |

---

## Historical Assets (Multi-Turn Conversation)

Pass assets generated in a previous turn that remain semantically compatible with the current request through `history_assets`:

```json
{
  "instruction": "Turn the image from the previous turn into a 3D model.",
  "assets": [],
  "history_assets": [
    {
      "type": "image",
      "asset_id": "img_a3f2c1",
      "source": "generated in previous turn",
      "description": "The cyberpunk nighttime Tokyo street image generated in the previous turn: a low-angle view with cool blue tones, neon reflected on pavement, and no people."
    }
  ]
}
```

Claude can reference the asset directly in the execution graph with `asset_ref: "img_a3f2c1"`; it does not need to regenerate the image.
